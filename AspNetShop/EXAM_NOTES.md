# Шпаргалка к защите экзаменационного проекта

Короткие ответы на вероятные вопросы преподавателя по проекту «ТехноМаркет».
Полная карта «требование → файл» — в [README.md](README.md).

## ASP.NET Core: принципы

- **Что такое middleware и конвейер запросов?** Каждый запрос проходит цепочку компонентов (`app.Use...` в `Program.cs`). Порядок важен: сначала сжатие и security-заголовки, потом статика, routing, аутентификация («кто ты»), авторизация («что можно»), сессия, кэши, и в конце endpoints (MVC). Middleware может обработать запрос сам или передать дальше через `next()`. Свои примеры: `SecurityHeadersMiddleware`, `RequestLoggingMiddleware`.
- **DI (Dependency Injection).** Сервисы регистрируются в `builder.Services` и внедряются через конструкторы. Время жизни: `Singleton` (один на приложение, напр. кэш), `Scoped` (один на запрос — DbContext и наши сервисы), `Transient` (новый каждый раз). Контроллеры зависят от интерфейсов — это упрощает тестирование.
- **Kestrel** — встроенный быстрый кроссплатформенный веб-сервер; в проде обычно стоит за обратным прокси (Nginx/IIS).
- **Конфигурация**: `appsettings.json` → `appsettings.{Environment}.json` → переменные окружения → аргументы командной строки. Окружения Development/Production задаются `ASPNETCORE_ENVIRONMENT`; в проде включаются HSTS и «тихая» страница ошибок, в разработке — Developer Exception Page.
- **MVC**: Model (данные и ViewModel), View (Razor), Controller (тонкий: валидация → вызов сервиса → результат). Бизнес-логика вынесена в сервисы, а не в контроллеры.
- **Areas** — способ разделить большое приложение на разделы со своими контроллерами/представлениями (у нас админка).
- **Tag Helpers** (`asp-for`, `asp-action`) генерируют HTML и ссылки с учётом маршрутов и валидации; Razor по умолчанию экранирует вывод → защита от XSS.

## AJAX

- **AJAX** — асинхронные запросы из JavaScript без перезагрузки страницы. Используем современный `fetch API` (преемник `XMLHttpRequest`, на котором строился классический AJAX и jQuery `$.ajax`).
- В проекте два приёма:
  1. **PartialView**: сервер возвращает готовый HTML-фрагмент сетки товаров — нет дублирования разметки.
  2. **JSON API**: сервер возвращает данные, клиент рендерит сам (подсказки поиска, быстрый просмотр, состояние корзины).
- Практики: debounce (не дёргать сервер на каждый символ), `AbortController` (отмена устаревших запросов), индикатор загрузки, History API (URL отражает фильтры), обработка ошибок тостами.
- AJAX-POST тоже защищаем от CSRF: токен из скрытого поля формы отправляется в заголовке `RequestVerificationToken`.

## Логирование (встроенное)

- `ILogger<T>` внедряется через DI; категория лога = тип `T`. Уровни: Trace < Debug < Information < Warning < Error < Critical; фильтры настраиваются в `appsettings.json` без перекомпиляции.
- Провайдеры «из коробки»: Console, Debug, EventSource, EventLog. Мы добавили **свой** `FileLoggerProvider` (интерфейсы `ILoggerProvider`/`ILogger`) — пишет в `logs/app-дата.log`.
- Структурированные шаблоны (`LogInformation("Заказ #{Id} на {Total}", ...)`) вместо конкатенации строк — параметры не теряются и дешевле при выключенном уровне.
- `RequestLoggingMiddleware` измеряет время каждого запроса (`Stopwatch`), пишет в лог и в заголовок `X-Response-Time-Ms`; запросы медленнее 500 мс логируются как Warning.

## Кэширование

- **IMemoryCache** — быстрый кэш в памяти процесса: категории и хиты. Минус: не шарится между серверами.
- **IDistributedCache** — абстракция распределённого кэша (у нас реализация в памяти, хранит сессии корзины; в проде подключается Redis без изменения кода).
- **OutputCache** — кэширует весь HTTP-ответ на уровне middleware по политике (время жизни, vary by query, теги для сброса).
- **ResponseCaching / Cache-Control** — HTTP-кэширование у клиента и прокси; статику отдаём с `max-age=30 дней`, а `asp-append-version` добавляет хэш файла в URL, чтобы после обновления браузер не использовал старую версию.
- **Инвалидация** — главная сложность кэша: после CRUD в админке сбрасываем `IMemoryCache` и тег OutputCache `catalog`, иначе витрина покажет устаревшие цены.

## Безопасность

- **Аутентификация vs авторизация**: Identity проверяет пароль (хэш PBKDF2 с солью — пароль в БД не хранится), политики и роли ограничивают доступ (`AdminOnly`).
- **CSRF**: Antiforgery-токены во всех POST, включая AJAX; куки `SameSite=Lax`.
- **XSS**: Razor экранирует вывод; CSP запрещает чужие скрипты; на клиенте при вставке JSON в HTML используем экранирование (`escapeHtml`).
- **SQL-инъекции**: EF Core всегда параметризует запросы.
- **Брутфорс**: Rate Limiting (10 попыток/мин на вход) + блокировка аккаунта Identity после 5 ошибок.
- **IDOR**: заказ ищется по паре `(Id, UserId)` — чужой заказ неотличим от несуществующего (404).
- **Open Redirect**: после входа редиректим только на локальные URL (`Url.IsLocalUrl`).
- **Загрузка файлов**: whitelist расширений, лимит размера, имя — Guid (нет path traversal и исполняемых файлов).
- **Транспорт**: HTTPS-редирект, HSTS; кука сессии `HttpOnly` (+`Secure` в проде).

## Производительность

- **Сжатие** Brotli лучше Gzip для текста; включён и fallback.
- **EF Core**: `AsNoTracking` на чтение (не тратим память на трекинг), проекции `Select` (выбираем только нужные колонки), пагинация на сервере, индексы под частые запросы, пул контекстов, `AsSplitQuery` против «взрыва» строк при Include коллекций.
- **Async везде**: пока ждём БД, поток Kestrel обслуживает другие запросы; `CancellationToken` отменяет ненужную работу при уходе клиента.
- **Кэширование** (см. выше) — самый дешёвый способ ускорения: запрос, который не дошёл до БД, самый быстрый.
- **Фронт**: ленивая загрузка картинок, лёгкие SVG, один CSS/несколько JS без тяжёлых фреймворков, AJAX вместо полных перезагрузок.
- Как измеряем: заголовок `X-Response-Time-Ms`, Warning-логи медленных запросов, `/health`, при необходимости — профилирование и логи SQL EF Core.

## Возможные вопросы «на подумать»

- *Почему SQLite, а не SQL Server?* Для учебного запуска без установки сервера БД; провайдер EF Core меняется одной строкой (`UseSqlServer`) — код сервисов не меняется. Ограничения SQLite: слаб при конкурентной записи.
- *Почему EnsureCreated, а не миграции?* Упрощение для демо; в проде — миграции (команды в README), потому что EnsureCreated не умеет обновлять существующую схему.
- *Как масштабировать на несколько серверов?* Сессии/кэш → Redis (`IDistributedCache`), статику → CDN, БД → серверная СУБД, приложение стейтлесс → можно ставить за балансировщик; Data Protection keys — в общее хранилище.
- *Что будет при отключённом JavaScript?* Каталог, карточка и формы работают серверно (первый рендер — MVC); AJAX — прогрессивное улучшение, а не единственная точка входа.
- *Как подключить оплату?* Отдельный сервис платёжного шлюза (ЮKassa/Stripe): создание платежа → редирект/webhook о статусе → обновление заказа; данные карты на нашем сервере не храним.
